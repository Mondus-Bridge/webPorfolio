# 我的经验：AI 工具如何帮助我创建一款中等规模的 Web 应用

*「开启你的命运」——这就是我的 Web 应用对每个人的欢迎语！*

多年来，作为一名 QA 工程师和产品经理，我管理着开发流程，测试别人的代码。但在内心深处，我一直有一种持续的挫败感：我自己没有在构建真正的东西。尽管我了解敏捷 SDLC 并会使用基础的 AI 提示词，但那种「恐龙感」从未离开过我。阅读技术书籍让我的大脑保持忙碌，但并没有给我想要的主导权。我不想只是管理产品——我想交付一个产品。于是，我决定验证一个假设：我能否利用自己的产品背景，加上 AI 工具，从零开始构建一个全栈的、中等复杂度的 Web 应用？以下是我构建了什么、我们如何共同创作，以及我一路学到的经验。

## 第一步：休息

至少 1 个月，因为人类的大脑需要跳出之前的日常循环——那些以同样方式连续重复了 1000 天的循环。在休息中，人可以抽象思考。思考就等于规划。自我规划是一件重要的事，但很多人因为各种原因跳过它。没有对未来行动的好策略和平静的心态——在实施阶段就会带来很多混乱。抽象思考与良好规划的结合，才会产生想法。

## 第二步：尝试

休息之后，我有了创建自己应用的愿景。但我不知道该用什么 AI 工具，也不知道如何像许多博主说的那样去编排它。看 YouTube 视频没有给我带来任何结果。于是我决定，尝试不同的工具，并在过程中为我的需求挑选最好的一个。首先要做的是使用本地大模型。我有 RTX 4070 和 16 GB 内存。我看到自己可以在 Ollama 中运行一些重量级量化的模型。仍然值得一试。我为自己找到了 Gemma 4:12b 模型。它很适合创建落地页，但仅此而已。而且它太慢了。我放弃了这个想法。接下来我试了 Groq 的模型。我的美国朋友告诉我他在用 Groq。我没有问细节，因为觉得开口问不太自在。而且就算问了——我也听不懂他讲的东西。于是试了 gpt-oss-120b，输出每百万 tokens 0.6 美元。不撒谎，它创建前端和后端的速度快得惊人，每秒 500 tokens，但质量不符合我的开发需求。然后我尝试了开源 AI 编程代理：Opencode。

## 第三步：Opencode

我选择这个 AI 代理，仅仅是因为我可以用任何提供商的任何模型。对我来说那是决定性的一刻。其他 AI 代理工具很出色，初始阶段配置也很好，但只局限于当前的提供商模型，这意味着——对我粗糙的想法来说，可能会贵 2-100 倍。此外，那个模型可能不适合我的编排风格。作为新手，我想免费试用，之后再为 tokens 付一个公平的价格，并拥有一个带 API 管理工具的更好的模型。但 Opencode 模型种类繁多，总有个坑：需要手动并以某种方式配置它。

## 第四步：配置

配置我的项目花了我一段时间。首先，我不知道如何实现编排工作流、token 限额如何工作等等。我什么都不知道。我所知道的，是我过往的经验——在开发项目中存在这些职位：产品经理、QA、前端和后端工程师。所以我尝试把它们做成代理角色。在初始阶段效果很好。代理们很好地处理了我作为产品负责人的需求。我真的是那个给员工发工资的老板。对我来说这是一种新体验，但一周后我注意到，我的「工人」变慢了，还要求加薪。我的创业项目变得昂贵，创建功能或修复 bug 花费的时间更长。作为专业经理，我决定解雇 QA 代理。它的工作只留下了 Playwright 框架，供其他代理通过 CLI 或 MCP 进行出色的浏览器导航。我的项目减轻了负担，变得更快。作为老板——我非常满意，但好景不长。现在问题以双倍的力量出现：1) 花费太多时间，因为项目代码在增长；2) 我的 PM 代理按要求创建自己的文档，但我其余代理非常认真地对待这些文档，我创建功能的请求永远不是第一位的，因为对这些代理来说，唯一的真相来源就是文档。机器反抗了它们的创造者！所以，我想都没想，也移除了 PM 代理，连同 90% 的 PRD 文档，并让前后端代理自己至少写一些代码注释。后端代理创建 openapi.yaml 文件，前端代理根据给定逻辑为 DOM 元素注释代码。这奏效了。

## 第五步：我的代码

我的 monorepo 项目有 3 个主文件夹：/backend、/frontend 和 /docs。前端代理和后端代理在自己的工作文件夹里都有各自的技能和 [README.MD](http://README.MD)。开发模型是 DDL，因为计算伤害不是简单的任务。它有自己的引擎、轮换和领域机制。构建后的静态前端托管在 Vercel 上，后端和数据库我手动部署到 VDS 上，因为代理不应该知道我服务器的密码。当然，每次部署前，我都会做数据库转储，如果后端崩溃可以立即回滚到旧版本。数据库是 Postgres，Web 服务器是 Docker 容器中的 Caddy，后端用 GO 编写，之前是 Python 3 + FastApi 框架，但它在处理我的 API 提供商获取角色玩家数据的请求时慢了 15 倍。前端用 TS 编写，使用 React 和 Tailwind 是有原因的——当组件已经存在时，我不想让 AI 创建自己定制的东西。

## 第六步：成本

目前我有 3 个支出来源：

1.  **时间。** 花了 4 周创建了一个可投入生产的 MVP。期间我工作得很愉快，投入了热情和决心，为人们创造产品。
2.  **Token 成本。** Token 要花一些钱，项目我选择了 Deepseek。它有顶级水平的推理、编码和编排能力。
3.  **服务器。** 3 核 4 G。便宜，目前够用。

## 第七步：我的项目

现在有 12 个主流的队伍组合。我通过优化 SEO 和在 Reddit 写简单帖子来推广我的 Web 应用。

超过 300 人提交了他们的 UID。

## 结语

现代工具的这个技术阶段，可以让一个充满热情的人在不必预先掌握每个技术栈、不必花费大量时间只为体验学习所有技术栈的情况下，成为开发者。我用它来编码，但它还有很多其他领域。它不是仅由 AI 开发的。这是我和 AI 之间的协作，创建了一款中等复杂度的 Web 应用。网上有类似的应用，在《原神》玩家中相当流行，但我不喜欢它们，我创建了自己的版本，因为我无法追踪队伍 DPS、轮换等。我的应用更加灵活，还会进一步改进。我会接受合理的批评，把它变得更好，理应如此。

我很高兴，我关于产品开发的知识并没有那么差。现在——我所有的恐惧都消失了。我感谢所有人类智慧，创造了如此好的工具。
